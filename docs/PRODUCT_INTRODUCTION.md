# Narrative Writing Workbench · 产品介绍

> 先找到值得说的话，再把它写成有分量的文章。
> A meaning-first narrative writing harness — not a "make it more literary" wrapper.

## 它解决什么问题

大多数 AI 写作工具的问题是**两头都不行**：

- **选题平庸**——让它给话题，还你"沟通很重要""AI 是一把双刃剑"；
- **落笔注水**——观点还没立住，先输出一堆漂亮的空话。

本工作台把"写"拆成两段工程：**意义发现（Meaning Discovery）**与**写作执行（Writing Execution）**。系统先回答"这篇到底要说什么、从哪个角度说、读者会经历什么"，再动笔。它的设计目标是一个明确的优先级：

```
意义推进 meaning progression
  > 读者状态保真 reader-state fidelity
  > 自然行文 natural prose
  > 风格装饰 stylistic decoration
```

## 三种开始方式

| 入口 | 适合 | 系统做什么 |
|---|---|---|
| **从一个话题开始** Quick Write | 你只有一个念头，甚至念头都没有 | 话题发现引擎批量生产锋利命题 → 你挑一条 → 找角度 → 写初稿 |
| **从素材写起** Write from material | 你有笔记、见闻、资料 | 素材入库 → 意图精炼 → 贴地生成初稿 |
| **改一篇旧稿** Improve a draft | 你已有一篇不太对的旧文 | 段落级诊断 → 局部修订补丁，不重写全文 |

## 话题发现引擎（核心差异化）

话题不是"想出来的"，是**从世界结构里发现出来的**。系统内置 World Topic Taxonomy V1.0 作为生产资源：

- **49 个现实领域**（Surface Domains）：教育、职场、AI、亲密关系……
- **313 个具体对象锚点**（Object Taxonomy，18 组）：平台、算法、导师、彩礼、学区房……
- **33 条目标冲突轴**（Tension）：自由↔安全、优化↔冗余、透明↔隐私……
- **12 种重构动作**（Reframes）：美德反转、缺陷即功能、自由→风险转移、指标→目标替代……

生成时遵循"锋利命题"标准 —— 追求的不是"这话挺有道理"，而是：

> "等等，好像真的可以这样理解。"

像这样的句子才是目标产物：**努力是奴隶的美德。 / 没有退出权的选择，不是真正的选择。 / 系统最稳定的时候，是人开始把系统造成的失败归咎于自己。**

每条候选都要过四因子评分（框架距离 × 解释力 × 压缩度 × 可辩护性）和"五秒测试"（普通人五秒内说得出同样的话，淘汰）。陈词滥调、心理学套话、抽象伪深刻、无依据的绝对化、标题党——全部在生成端拦截。

**两种生成模式：**

- **种子模式**：你在话题框写下自己的直觉（"女人会爱上伤害她的男人…"），一批 8 条就是同一现象的 8 个**切面**——间歇强化、信号贬值、幸存者证据、退出成本……各自立在不同机制上，绝不换说法。
- **漫游模式**：只选领域不写话题，系统在该领域内铺开 8 条，每条锚定不同对象、坐在不同张力轴上，整批覆盖不同子域。

工程细节：新生成的话题按领域显示在“本次生成”，不会自动成为长期数据；用户明确收藏后才进入本机 SQLite 选题箱，可搜索、备注、归档并关联写作任务。**永远 AI proposes, user accepts**——选择话题只会填入输入框，收藏和开始写都必须由用户明确触发。

## 写作执行：意义先行

确认话题后，系统不直接续写，而是先在内部完成：

1. **意义发现**：这个话题值得说的角度是什么？读者读完应该发生什么变化？（不满意可一键换角度）
2. **WIR 写作意图表示**：把角度编译成有推进结构的 beats 大纲——意义在每一拍之间生长，而不是段落之间堆砌。
3. **写作与保真门**：初稿生成后过语言修复与 fidelity gate——**偏离意图结构的漂亮句子会被拦下**。
4. **写作地图**：正文段落与意图节拍对齐可视化，让你看到"写出来的"和"想说的"是否同一件事。

## 工作台：像改论文一样改 AI

生成之后不是结束，是协作的开始：

- **段落级审阅**：指出哪里没有推进、哪里在灌水，问题带位置；
- **选区修订补丁**：选中文字 → 提修改意图 → 看到 before/after 对照 → 你决定 accept 还是 reject。接受才产生版本；拒绝不改正文，提案状态仍可追溯；
- **版本历史与 diff**：每一次接受、每一次恢复都是新版本，永远可回退；
- **局部修改，不重写全文**：只改你选中的，锁住你不能动的。

## 本地优先，随时可换大脑

- 单文件 SQLite + 无账号无云依赖，`scripts/launch_workbench.sh` 一键起，闲置自动退出；
- 引擎可换：**mock 演示模式**零 key 全功能可玩；真实模式在 Settings 填 key/base-url/model 即可热切换。OpenCode Go 的现场主链路已用 `deepseek-v4-flash` 完整跑通；模型清单与短连接测试只证明可调用，首次使用仍应先做一篇容量试跑；
- 提示词全部外置于 `prompts/`，结构化输出有 schema 校验，中间产物全部持久化——这是一台可审计的写作认知装置（Writing Cognition Harness），不是黑盒。

## 明确不做什么

不做微调、不做 RAG 检索增强、不做作者风格提取、不做"更文学一点"的通用润色壳子。当前产品聚焦：话题发现、topic-only 与素材落地的初稿生成、局部修订，以及本地可追溯的数据与检查流程。涉及强事实的话题会提示你先补充素材，文章不会假装引用来源。

## 快速开始

```bash
./scripts/launch_workbench.sh        # → http://127.0.0.1:8600
# 无 key 也能玩：Settings 切到 mock 引擎
# 真实生成：Settings 填 OpenCode Go key + deepseek-v4-flash，保存即生效
```

打开 Quick Write，什么都不用想，点「✦ 生成一批话题」——从 8 个锋利的切面里挑一个，按下「开始写」。

模型兼容性会直接影响等待与成功率。同一 API、同一任务的实测中，`deepseek-v4-flash` 完成全链路；`mimo-v2.5` 在长 Meaning Discovery JSON 上两次达到输出上限并返回截断结果。后者可以继续用于经过验证的短任务，但暂不推荐承担完整文章主链路。
