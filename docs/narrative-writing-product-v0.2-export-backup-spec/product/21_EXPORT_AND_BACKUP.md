# 21 — Export and Backup

## 用户结果

用户完成写作后，可以把当前保存的正文或任意历史版本下载为 Markdown/纯文本。备份用于灾难恢复和设备迁移，恢复结果位于独立工作区，不覆盖正在使用的数据。

## E1/E2 文本导出流程

### 当前工作副本

1. 用户选择 Markdown 或纯文本。
2. 前端等待中文输入法 composition 结束并捕获编辑器内容。
3. 前端完成 autosave；失败时保留输入并停止。
4. 前端用服务端返回的最新 revision 请求导出。
5. 服务端在同一数据库临界区读取并核对 revision，再返回下载。

当前稿导出的是 `drafts.working_content`，不是 `current_version_id` 指向的旧内容。导出不会自动创建版本节点。

### 指定历史版本

版本历史中每行都可按当前选择的格式下载。内容来自不可变的 `versions.content`，导出不会恢复该版本，也不会改变当前 Draft。

## 内容规则

- `include_title=false`：响应正文与数据库内容逐字一致，包括中文、空行、Markdown 字符和表情。
- `include_title=true` 且任务标题非空：Markdown 使用一级标题和一个空行；纯文本使用标题和一个空行。
- 空标题不添加占位标题，只影响下载文件名回退。
- UTF-8，无 BOM；不规范化正文换行或尾部空白。
- 普通文章导出不包含素材、计划、意义发现、审阅、补丁、版本元数据、模型调用或设置。

## UI

- 工作台标题栏提供格式选择和“导出当前稿”。无正文时禁用。
- 版本页提供共享格式选择和逐版本“导出”。
- 成功后提示已下载；保存/冲突/下载失败显示原错误，且不创建空文件。

## E3–E5 备份与恢复

第一版备份整个工作区：一致性数据库快照、manifest 和校验信息。它不包含 `workbench/settings.json`、环境变量、API Key、临时评估、日志或浏览器存储。

恢复分为预检和落盘。预检不写目标库；正式恢复只能创建不存在的新目录/数据库。合并进当前库、选择性项目恢复和覆盖恢复不在本版范围内。
