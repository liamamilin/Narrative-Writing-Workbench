# 24 — Angle Confirmation Flow

## 两条入口

Quick Write 的“开始写”保持原链路：创建任务后进入工作台，自动完成意义发现、结构与正文。

“先看角度”执行以下有界流程：

1. 用当前话题、写作模式、角度模式和写作配置创建 topic-only task。
2. 用户确认事实提醒后，显式触发一次候选发现。
3. 页面显示 3–5 张角度卡。每张只含主张、机制、核心问题、边界和读者带走的工具。
4. 用户选择一张。可展开编辑并一次提交完整的五个可编辑字段：主张、核心问题、深层含义、边界、读者收获。
5. “确认并开始写”先保存不可变确认快照，再进入原工作台，用该快照生成正文。
6. “再找一批”是另一项明确操作；旧候选只留作历史和避重依据。

## 编辑语义

编辑不是一个后台优化请求。服务端逐字保存用户提交的字段，并把它们同步到选中 candidate 和 meaning 顶层。候选自带的机制、反例和裂缝继续保留；如用户希望模型重新整理，应在后续独立功能中通过明确操作实现，本版不暗中调用。

## 输入变化

候选绑定确认时的 topic、writing_mode、angle_mode、custom_angle 和会影响写作的配置。任一值变化，候选仍可查阅，但标记过期且不能确认；已确认快照也不能用于新的生成。追加素材会把任务转为 source-grounded，因此 topic-only 确认快照同样拒绝使用。

## 失败恢复

候选发现失败不产生确认快照或正文。确认后 Writer 失败，确认快照继续存在；用户重试时显式带回同一个 confirmed_meaning_id，不重新选择，也不重新运行 Meaning Discovery。
