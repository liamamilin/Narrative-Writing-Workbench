# 27 — Revision Worklist Flow

## 用户流程

1. 用户保存当前正文并运行检查。
2. 系统把能在该 revision 精确定位的问题保存为修订条目，按严重程度和原顺序优先显示三项。
3. 用户可定位原文、跳过一项，或选择“处理此项”生成一个局部提案。
4. 用户也可在正文选择连续段落并标记“保留原文”。保留范围显示在正文和检查面板中，可主动取消。
5. Patch 返回后先做保留校验，再显示 Before/After。Accept 前再次在事务里校验 revision、锁、锚点和当前保留范围。
6. Accept 创建 Version 并把关联条目标记 resolved；同次 Review 的其他 open/proposed 条目因正文变化成为 stale。
7. Reject 只拒绝提案，关联条目恢复 open；Dismiss 把条目标记 dismissed，均不改变正文。

## 锚点规则

初版工作单与保留范围以连续完整段落为单位。每个锚点保存：base revision、全文 SHA-256、1-based 段落范围、Python 字符索引 `[start,end)` 和精确 quote。生成提案前全部字段必须与当前正文一致。

重复段落由字符索引区分。手工编辑后不做模糊重定位：旧工作单和保留范围明确标记 stale。接受局部 Patch 时，完全位于修改范围外的保留文字可按字符差值确定性重定位；与修改范围相交的保留文字只有在新全文中存在唯一、逐字相同的 quote 时才能继续，否则拒绝 Patch。

## 单项推进

同一工作单最多一个 `proposed` 条目。必须先接受或拒绝当前提案，再处理下一项。这样下一项始终基于当前 revision，不会把多个旧补丁顺序叠加。
