# 下一阶段开发优先级

日期：2026-09-13。依据当前代码、Product V0–V0.7 规格、实施报告和未完成人工验收排序。

## 当前基线

F01–F06 工程实现已经完成；源码隔离全量 369 项、浏览器自动化 B01–B17 及对应 GitHub Actions 均通过。当前两类主要风险是：真实模型输出是否帮助用户写得更好，以及真实输入、编辑、保存和恢复是否足够可靠。

因此，下一阶段按对核心体验的影响排序。新页面数量、功能新鲜感和模型调用次数不作为优先级依据。

## 什么属于核心体验

产品主链路是：

```text
找到值得写的话题 → 确认值得说的角度 → 生成可用初稿
→ 安全编辑/保存 → 找到关键问题 → 局部修订并由用户接受
```

直接决定这条链路能否成立的能力属于核心体验：

| 层级 | 能力 | 对体验的影响 | 当前缺口 |
|---|---|---|---|
| C0 核心价值 | 真实模型的命题、角度和初稿质量 | 决定产品是否产出“值得读”的文章 | 12 例工程运行完成，独立人工质量评分未回收 |
| C0 核心价值 | F02 写前角度确认 | 决定用户是否在动笔前避开错误角度 | 工程通过；候选质量、选择成本和重写减少量待评估 |
| C0 核心操作 | 中文输入、选区、autosave、冲突与恢复 | 任何丢字、错存或覆盖都会破坏写作主流程 | 自动化通过；真实输入法与完整键盘走查待完成 |
| C0 核心操作 | F03 修订工作单、Before/After、Accept/Reject | 决定“局部修改、不重写全文”是否可信 | 工程安全已验证；真实问题命中和修订改善待评估 |
| C1 数据信任 | 导出、版本、备份恢复、选题持久化 | 决定用户是否敢把真实文章放进工作台 | 自动化通过；人工往返和可理解性待确认 |
| C1 特定入口 | F04 论点与素材依据卡 | 决定有素材非虚构写作是否会误导用户 | 错误支持、漏报和核查时间待真实评估 |
| C2 实验能力 | F05 稿件读者路径 | 可能改善结构诊断，但不是完成文章的必要入口 | 需证明比普通 Review 增加有效问题且值得等待 |
| C2 条件功能 | F07 候选稿对照 | 只在用户经常需要保留两稿时影响核心效率 | 尚无足够使用信号，不进入实现 |
| C3 新范围 | F08 研究辅助、F09 可编辑地图 | 扩展材料准备和结构试验范围 | 依赖 F04/F05/F07 的前置证据 |

F06 选题箱改善连续使用和数据留存，已经完成。它不再占用下一阶段开发资源。

## 更新后的执行顺序

| 排名 | 工作 | 影响级别 | 当前决定 |
|---|---|---|---|
| 1 | C0 真实写作质量评估 | 最高 | 先评命题/初稿与 F02 角度，回答产品核心价值是否成立 |
| 2 | C0 编辑与修订人工验收 | 最高 | 完成 B09、B10、B13、B14 的真实输入、键盘、角度与修订主流程 |
| 3 | C0/C1 缺陷修复 | 最高 | 上述验收出现丢字、覆盖、错误定位、越界修订或严重误导时立即修复 |
| 4 | C1 数据信任人工验收 | 高 | 完成 B11、B12、B17 的导出、备份恢复和选题迁移往返 |
| 5 | F04 真实效果评估 | 高但限定入口 | 单独报告错误支持、遗漏和用户核查时间 |
| 6 | F05 增量价值评估 | 中 | 与普通 Review 对照，不能只评界面或模型是否返回结果 |
| 7 | F07 产品发现 | 条件 | 只收集“两稿都想保留比较”的发生频率，满足启动信号后再写 V0.8 规格 |
| 8 | F08/F09 阶段 A | 后置 | 各做小规模可行性研究，不进入连续产品开发 |
| 9 | V1.2 剩余盲评 | 独立研究线 | 继续回收，不与产品试用评分混算 |

## 立即可执行的工作包

### P0-1：核心质量评审工具与评审包

预计 1–2 人日开发准备，另需等待至少两名独立评审者。

1. 扩展现有匿名评审工具，为基础初稿、F02 角度候选和 F03 修订前后分别建立适用评分字段。
2. 固定模型、配置、prompt 版本和输入案例；评分标准在看结果前锁定。
3. 生成不含模型名、自动结论、原案例编号和运行状态的评审包。
4. 至少两名评审者独立评价命题/推进、可辩护性、角度价值、补丁改善和非目标损伤。
5. 分别形成继续、收缩、修正或关闭决定；不以综合均分掩盖致命失败。

退出条件：基础生成、F02、F03 都有两份完整独立结果；能回答角度确认是否减少错误方向，以及修订是否在不伤害上下文的前提下改善目标问题。

### P0-2：核心交互人工走查

预计 0.5–1 人日，不含问题修复。

1. 先执行 B09、B10、B13、B14：真实中文输入法、段内/跨段选择、键盘焦点、角度确认和修订接受/拒绝。
2. 再执行 B11、B12、B17：当前稿导出、独立恢复、旧选题迁移和清空浏览器存储后的持久化。
3. B15 作为有素材入口专项；B16 作为实验能力专项，分别记录，不阻塞前两组核心结论。
4. 使用 `tests/browser/MANUAL_ACCEPTANCE.md` 填写环境、评审者、结果和复现步骤。

退出条件：每项有具名结果；阻断问题修复并完成自动化与人工复验。自动化通过不能代替真实输入法和人工判断。

### P1：F04 与 F05 分开决策

F04 必须统计错误支持、遗漏重要陈述和核查时间。只要存在频繁错误支持，就先收缩关系文案或入口范围。

F05 必须与普通 Review 对照新增有效问题、误报、修订改善和等待成本。若只是换一种方式复述 Review，保留历史产物并关闭独立入口扩展。

## 后续功能决策门

- F07：真实使用中频繁整稿重写，并且用户明确需要保留两个生成方案比较时，才进入 Product V0.8 规格。
- F08：F04 对用户材料的关系判断达到可接受水平，且实际任务主要卡在材料准备时，只启动阶段 A。
- F09：F05 能稳定定位人工认可的结构问题，且候选隔离能力可防止结构试验覆盖当前稿时，只启动阶段 A。

当前执行主线是：`核心质量评审工具 → 核心交互人工走查 → 修复阻断问题 → F04/F05 分项决策 → 根据证据选择后续功能`。
