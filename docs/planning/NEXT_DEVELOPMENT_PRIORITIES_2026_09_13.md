# 下一阶段开发优先级

日期：2026-09-13。依据当前代码、Product V0–V0.6 规格、实施报告和未完成人工验收排序。

## 判断

F01–F05 的工程链路已经完成，并通过 359 项 Python 测试、源码隔离回归和浏览器 B01–B16。当前最大的风险不再是缺少功能，而是尚未证明真实模型产生的角度、工作单、材料关系和读者路径确实帮助用户完成文章。

因此，下一阶段采用“先补证据，同时只推进一个低风险功能”的顺序。不能把更多页面和模型调用当作进展，也不能在 F04/F05 的判断质量未知时直接扩大到联网研究或可编辑结构图。

## 立即执行顺序

### P0-A：人工交互验收

预计 0.5–1 人日，不含发现问题后的修复。

1. 使用真实中文输入法完成长文输入、候选上屏、段内与跨段选择。
2. 在 1280×800 和 1440×1000 下走通正文、检查、依据卡、稿件路径、版本和恢复。
3. 只用键盘完成关键动作，验证对话框、失败提示和焦点恢复。
4. 按 `tests/browser/MANUAL_ACCEPTANCE.md` 具名记录环境、结果和复现步骤。

退出条件：B09–B16 每项有明确结果；阻断级问题修复并回归，不以自动化结果代替人工记录。

### P0-B：真实效果决策

预计 2–3 人日准备和运行，另需等待至少两名独立评审者。

1. 固定模型、配置、prompt 版本和输入案例，不在看结果后修改评分标准。
2. 复用匿名评审协议，补充 F02 角度选择、F03 局部修订、F04 支持关系、F05 路径问题的适用评价字段。
3. 对每项记录有效命中、误报、遗漏、接受/拒绝、修订前后判断、总等待和失败。
4. 分别作出继续、缩小、合并或关闭入口的决定。

退出条件：至少两份独立评审完成；F04 报告错误支持和遗漏，F05 报告相对普通 Review 的新增有效问题，不能只给综合均分。

### P1：F06 本地选题箱

预计 2–4 人日。P0 的评审材料提交给评审者后即可开始，不必空等人工回收。

1. 编写 Product V0.7 增量规格与实施评审。
2. 数据库增加 idea、状态、标签和 task 关联；升级及备份契约随 schema 版本更新。
3. 将现有 localStorage 收藏幂等迁移到 SQLite，服务端确认前保留原数据。
4. 提供搜索、过滤、收藏、归档、继续写和打开原任务。
5. 增加专项测试及浏览器 B17，验证清空浏览器缓存后仍可读取，重复迁移不产生重复项。

退出条件：选题可跨浏览器会话继续使用；迁移可重试；F01 备份恢复包含新记录；Quick Write 原流程保持可用。

## 后续决策门

- F07：真实使用中频繁发生整稿重写，并且用户需要在两个已生成方案之间保留选择时启动。
- F08：F04 对用户提供材料的关系判断达到可接受水平，且真实任务主要卡在材料准备时，只启动阶段 A。
- F09：F05 能稳定定位人工认可的结构问题，且候选隔离已可防止结构试验覆盖当前稿时，只启动阶段 A。

当前工程顺序是：`人工验收准备 → 真实效果评审发出 → F06 → 根据证据选择 F07/F08/F09`。若评审暴露正文安全、数据恢复或严重误导问题，立即暂停新功能并回到缺陷修复。
