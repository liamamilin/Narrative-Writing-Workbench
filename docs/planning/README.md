## 当前建议

先完成现有产品的提交安全、版本关联与主流程可靠性，再推进“本地导出与备份”和“写前确认卡”。随后依据真实使用中的主要问题，选择“修订工作单”或“论点与素材依据”；其余候选按验证结果启动。

| 阶段 | 任务编号 | 退出条件 |
|---|---|---|
| R0 稳定性与验收 | S00–S08 | 关键一致性问题关闭，干净环境可测，三种入口通过浏览器验收，效果基线可追溯 |
| R1 完成写作与写前控制 | F01、F02 | 正文可靠导出/恢复；用户可先确认角度再写，默认快速流程仍可用 |
| R2 可控修订与依据 | F03、F04 | 改动可逐条决定，素材引用可回查，过期诊断不误用于新稿 |
| R3 定向探索 | F05、F06、F07 | 每次选择一个验证假设，有证据再扩大 |
| R4 新范围研究 | F08、F09 | 完成前置验证与独立产品规格后再进入实现 |

R0–R4 是规划批次，不是已发布版本号。S 表示现有产品收口任务，F 表示候选新功能；原始计划表保留初始状态，实际进展统一更新到开发日志，不以计划代替验收。

## 规格关系

Product V0 及 Quick Write V0.1 仍是当前产品的权威规格；本组规划不覆盖它们。实现 R0 前更新现有实现评审，记录新增数据/API 契约及兼容策略。实现新功能前，将选定批次写成扩展规格及验收标准。

用户本次明确要求规划新功能，因此路线图可以讨论当前版本范围之外的方向；这不意味着已经实施它们。旧 `docs/13_FUTURE_ROADMAP.md` 保留为历史引擎研究路线，不能据此自动启动引擎扩展。

## 维护方式

- 开发任务状态使用：未开始、进行中、待验收、完成、阻塞；完成时补提交、验证命令和报告路径。
- 新功能状态使用：提案、验证中、进入规格、开发中、验收、搁置；以用户问题和验证结果驱动状态变化。
- 保留 2026-09-13 检查报告作为历史基线；后续修复结果另加报告，不改写当时发现。
- 工作量均为单人估计，不含等待人工评审或提供方恢复的时间，也不构成自动排期。
