# Product V0.6 读者路径检查实施报告

日期：2026-09-13。状态：R0–R6 已完成；真实模型效果评估待进行。依据 [V0.6 增量规格](../narrative-writing-product-v0.6-reader-path-spec/README.md)。

## 产品结果

工作台中原有的 Writing Map 已明确命名为“原定路径”，用于回看生成时的结构计划。新增“稿件检查”分析当前实际正文，逐段显示主作用、增加的认识、提出的问题和回答的问题，并把可可靠定位的重复、推理跳跃、未回答问题和转折不清显示为路径问题。

页面明确说明这是模型对可能阅读效果的诊断，不是真实读者实验。未运行时只显示功能说明和开始按钮，不生成伪造分析。路径步骤和问题均可定位正文；问题可跳过或进入已有的 ProposedPatch 流程，接受前正文不变。

## 离线继续开发门槛

实现前建立了三类无需领域知识即可核对的固定样例：相邻段落逐字重复、缺少中间依据的“因此”结论、正文提出后没有回答的明确问题。Mock 在这些样例上输出完整逐段路径并命中对应问题，证明产物比现有 Review 的维度评分多出可检查的段落推进信息，因此通过契约级继续开发门槛。

该门槛只验证流程和确定性规则。自然文章中的真实模型命中率、误报和局部修订收益仍需人工评价。

## 结构化产物与引用校验

产品 adapter 新增 `review_reader_path()`。Real adapter 使用外置 `prompts/reader_path_review.md` 和 Draft 2020-12 JSON Schema；Mock adapter 提供同形结果。输入限制为正文 30,000 字符、80 个非空段落、单段 10,000 字符，超过限制明确拒绝，不静默截断。

服务端要求每个非空段落恰好有一个步骤，段落编号有效且完整 paragraph quote 与当前正文逐字相等。缺失、重复或错误步骤使整轮检查失败，不落部分结果。问题必须在声明的段落范围内有唯一逐字引用；无法验证的问题会被丢弃，不创建可操作工作单。

## 数据、备份与修订安全

数据库 schema 从 v5 升为 v6。`reviews.analysis_type` 区分普通写作检查与读者路径检查，普通 Review 查询显式筛选 `writing`，两类检查不会相互覆盖。`reader_path_steps` 保存逐段只读产物，路径问题直接复用 F03 `revision_items`，不复制第二套问题状态机。

路径结果保存 Draft revision/hash。手工编辑、生成、恢复或接受 Patch 后，旧结果和仍开放的问题会过期；旧锚点不能继续跳过、提案或接受。路径问题的 Patch 仍在提案时和 Accept 事务中复核 revision/hash/quote；拒绝恢复待处理，接受创建一个 Version 并解决对应条目。

严格备份预检现支持 v3、v4、v5 和 v6。v6 校验路径步骤与 reader-path Review、Draft 的关系；旧备份恢复后由 Database 增量升级。

## 界面

中心栏提供“正文 / 原定路径 / 稿件检查”三个明确视图。“稿件检查”以双栏展示逐段推进和路径问题；路径卡支持 Enter/Space 定位。问题卡显示类型、状态、影响、原文和修改目标，并复用定位、跳过、处理、Before/After、接受和拒绝交互。正文改变后页面保留旧结果供回看，同时明确显示已过期并移除继续处理入口。
