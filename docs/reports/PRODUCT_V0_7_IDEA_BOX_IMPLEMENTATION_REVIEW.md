# Product V0.7 本地选题箱实施评审

日期：2026-09-13。依据 Product V0/V0.1、[V0.7 增量规格](../narrative-writing-product-v0.7-idea-box-spec/README.md)与 F06 规划。

## 产品理解与决定

现有 Quick Write 会把所有建议直接写入 `qw_topic_lib_v1`，因此“刚生成”和“用户决定保留”没有区别，数据又只属于单个浏览器。V0.7 将新建议保留为页面会话数据；明确收藏后才写入本地 SQLite 选题箱。旧库按无损优先迁为 `to_write`，来源标记为 `legacy`。

## 数据与 API

数据库升为 v7，新增 `ideas`。标准化仅做 NFKC、空白折叠、trim、casefold，不做语义合并。API 提供有界列表、创建/去重、备注/状态更新和最多 200 条的原子 legacy import。Task 创建增加可选 `idea_id`；校验 topic-only、话题相等和未关联状态后，在创建 Task 的同一事务写入关联。

严格备份增加 Ideas 表、状态索引与 task 关系检查；v3–v6 契约保持原样。升级前仍创建一致性迁移备份。

## 界面与状态

Quick Write 侧栏保留建议生成和键盘选择，新增“收藏当前话题”“本次生成”“选题箱”、关键词/状态过滤、备注、待写/归档和打开文章。页面启动时尝试旧库迁移；只有服务端完整确认才删除旧 key。

## 验证重点

专项测试覆盖标准化去重、输入边界、搜索/状态、原子导入、Task 关联失败安全、并发/重复创建、v6 升级和 v7 备份关系。浏览器 B17 覆盖旧库迁移、候选不自动持久化、收藏、刷新/清空 storage、过滤、备注、创建并重开任务。

主要风险是迁移后丢失旧浏览器数据、相似话题被错误合并、任务已创建但关联失败，以及新异步加载破坏 Quick Write 原有建议/角度流程。实现以服务端确认、窄标准化、单事务和 B10/B13/B17 回归控制这些风险。
